# 产品大图子项目说明

本目录负责制作 HTML 格式的产品全景大图。工作时同时遵循项目根目录 `AGENTS.md`。

## 当前目标

优先把复杂业务关系画正确、讲清楚，再增加交互和视觉细节。产品大图需要帮助产品新人理解：谁发起任务、Agent 如何解析、系统如何生产、人工在哪里确认、异常如何返回、素材和数据最后流向哪里。

## 建议文件

```text
product-map/
├─ AGENTS.md
├─ index.html
├─ styles.css
├─ app.js
└─ data/
   └─ product-map.js
```

需要增加文件时保持业务数据、样式和交互逻辑分离。

## 信息架构

默认采用从左到右主链路，通过泳道区分：

1. 运营与人工决策层；
2. Agent 理解与策略层；
3. 结构化配置与任务编排层；
4. 商品、品牌、频道和知识资产层；
5. 图片/视频模型与工程合成层；
6. 审核、素材、投放层；
7. 数据回流与效果分析层。

主流程使用实线，数据回流使用有区别的虚线或颜色，异常与重试使用警示样式。必须提供图例，不能只靠颜色传递含义。

## 必须出现的内容

- Agent 对话、意图解析、歧义识别、缺失信息追问和分阶段确认；
- 投放目标、目标人群、承接对象、选品、创意和素材规格；
- 商品 List 与推荐原因；
- 图片生成链路；
- 视频的创意结构、分镜、组件、模型片段与工程合成；
- 生产队列的排队、执行、失败、重试和人工接管；
- 审核队列的通过、驳回、重审和返回路径；
- 素材库与素材版本；
- 商品库、品牌资产库、频道规则库和创意知识库；
- 投放结果与数据回流；
- Schema、状态机和全链路追溯。

## 节点数据规范

每个核心节点至少包含：

- 稳定 ID；
- 节点名称与所属泳道；
- 业务目标；
- 输入；
- 系统处理；
- 输出；
- 用户动作；
- 可能状态；
- 异常与返回路径；
- 上游与下游；
- 追溯字段。

连线至少区分主流程、数据流、资产引用、异常返回和人工确认。

## 大图交互

按优先级实现：

1. 超宽画布的平移、缩放或清晰导航；
2. 顶部锚点快速跳到各业务域；
3. 点击节点打开详情面板；
4. 显示或隐藏主流程、数据流和异常流；
5. 切换业务视图、系统视图和状态视图；
6. 支持打印或导出清晰大图。

首版无需为了动效牺牲信息正确性。

## 视觉与可用性

- 默认简体中文、浅色背景、专业克制；
- 同类节点统一颜色、圆角、间距和图标语义；
- 确认点、队列、审核和异常一眼可辨；
- 中文字号不能过小；
- 宽屏优先，窄屏允许横向滚动，不强行压缩；
- 1920×1080 下主链路可读；
- 不允许连线遮挡关键文字或出现方向不明。

## 完成定义

静态大图完成的前提是链路、节点、状态和异常表达完整；交互式大图完成的前提是节点详情、视图切换和导航可用。每次完成后在浏览器检查 1440px 与 1920px 两种宽度、控制台错误、文字截断、连线遮挡和交互返回路径。
