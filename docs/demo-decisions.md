# 可交互 Demo v1 决策记录

## 已确认业务基线

- 保留“意图 → Agent 追问 → 需求确认 → 商品/承接确认 → 创意/分镜 → 预览 → 批量生产 → 审核 → 入库 → 投放 → 数据回流 → 策略沉淀”的完整顺序。
- 商品及点击后页面是进入创意的前置闸门；预览版本是创建批量任务的前置闸门。
- 视频拆为镜头片段、TTS/数字人/字幕等组件与工程合成；异常只重试受影响的镜头或组件。
- 审核驳回定位到文案、镜头、组件或合成环节，并创建新版本保留历史。
- 数据回流仅做记录、比较和观察，不声明自动归因。

## 原型补充假设

- 目标人群使用“25–35 岁、关注通勤与轻薄穿搭的女装新客”。
- 渠道使用通用短视频信息流，规格为 9:16、15 秒。
- 10 条视频按场景种草 4 条、利益点直给 3 条、搭配对比 3 条分配。
- 承接对象是虚构“清凉一夏”女装活动页。
- 商品、品牌、规则、模型、库存、价格和投放结果均为 Mock 数据。

## 实施决定

- 使用原生 HTML、CSS、JavaScript 和经典脚本加载，保证直接打开文件时离线可用。
- Mock 数据、初始场景、状态机、通用组件和页面渲染分文件维护。
- 主页面隐藏内部编号与复杂参数；版本、Prompt、模型、合成参数和投放关联放入详情抽屉。
- 页面只在业务人员需要判断的节点提供确认动作；自动步骤以系统说明或队列状态呈现。
- 使用内存状态，不写入本地存储；刷新和“重置演示”都恢复初始场景。

## 影响范围

- 需求状态决定选品是否可操作；商品和承接状态决定创意是否可操作。
- 创意与预览版本决定任务能否创建，并成为批量生产的冻结依赖。
- 局部失败记录影响生产队列、技术降级和质检返回路径，但不丢弃成功镜头。
- 审核结论影响素材版本、入库与投放资格；返工版保留父版本和原审核记录。
- 投放记录关联素材、商品、承接页和生产参数，供后续比较与人工复盘。

## v1 验收结果

- 已在应用内浏览器走通三轮追问、需求确认、商品排序、承接确认、分镜预览、10 条任务、审核通过/驳回、v2 局部返工、复审入库、模拟投放、停止投放与策略沉淀。
- 队列同时展示成功、处理中、部分失败、自动重试和技术降级；异常详情明确保留其他成功镜头。
- v2 素材追溯可查看需求、SKU、承接页、创意、Prompt、模型、分镜、合成、审核、素材和投放记录。
- 1440px 与 1920px 均无页面级横向溢出，生产表格和关键操作位于可视边界内。
- 浏览器控制台无 error 或 warning；重置按钮与页面刷新均恢复 0/9 的初始演示场景。
