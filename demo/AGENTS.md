# 产品 Demo 子项目说明

本目录负责在产品大图逻辑确认后开发可交互 Demo。工作时同时遵循项目根目录 `AGENTS.md`，并将 `product-map/` 中已确认的产品关系视为业务基线。

## 启动条件

开发某段 Demo 前，先确认对应业务链路、状态机和异常处理已经在产品大图或 `docs/` 中明确。若两处存在冲突，先记录冲突并请求用户确认，不要在代码中偷偷选择一个版本。

## 建议文件

```text
demo/
├─ AGENTS.md
├─ index.html
├─ styles.css
├─ app.js
├─ data/
│  ├─ scenarios.js
│  └─ mock-data.js
└─ components/
```

首版规模较小时可以简化，但业务数据、状态和界面渲染仍应分离。

## 首个贯穿场景

默认使用以下案例贯穿 Demo：

> 运营提出“从夏季女装中选择合适商品，生成 10 条竖屏促销视频，用于拉新，并将用户承接到活动频道”。

场景至少演示：

1. Agent 识别“10 条”的歧义和缺失渠道/人群信息；
2. 用户补充并确认结构化需求；
3. Agent 推荐商品并解释原因；
4. 用户确认商品 List、创意结构和分镜；
5. 创建批量生产任务；
6. 队列中出现成功、部分失败和重试；
7. 一个素材审核通过，一个因品牌或合规问题被驳回；
8. 驳回素材返回具体环节修改并重新送审；
9. 通过素材进入素材库并模拟投放；
10. 回流曝光、点击、转化数据，但只形成观察结论，不伪造强因果归因。

## 页面与能力范围

优先实现以下页面或工作区：

- Agent 工作台；
- 结构化需求确认；
- 商品选择与商品 List；
- 图片创意/视频创意与分镜确认；
- 生产队列；
- 审核队列；
- 素材库；
- 知识库/资产库；
- 数据看板。

可以使用单页应用式导航，但每个页面必须在主链路中有明确位置。

## Mock 数据规则

- 首期不连接真实模型、数据库、广告平台或付费 API；
- Mock 数据集中管理，不散落在事件处理函数和 HTML 中；
- 任务、商品、素材、审核和投放记录使用稳定 ID；
- 数据对象保留版本、来源、创建人、时间和关联 ID；
- 失败、驳回和重试必须有明确原因，不能只显示红色状态；
- 数据变化遵循状态机，不允许任意跳转。

## 交互原则

- Agent 分阶段确认，不一次展示几十个字段；
- 用户关键决定必须有明确确认动作和结果反馈；
- 自动步骤要说明系统正在做什么；
- 长任务进入队列，不用虚假加载动画冒充真实进度；
- 审核驳回能定位到商品、镜头、组件或文案；
- 用户随时能追溯素材来源和生产记录；
- 空状态、加载状态、失败状态和无权限状态都要有处理。

## 技术原则

- 首版优先原生 HTML、CSS、JavaScript；只有复杂度确实需要且用户同意时才引入框架；
- 默认可离线运行；
- 避免必须联网加载的字体、图标和脚本；
- 使用语义化 HTML、键盘可操作控件和清晰焦点状态；
- 状态转换集中定义，避免在多个点击事件中各写一套规则；
- 不为尚未确认的后端接口制造貌似真实的集成。

## Demo 验收

- 用户可以从提出需求走到素材入库和数据回流；
- Agent 至少真实演示一次追问、一次推荐解释和一次分阶段确认；
- 生产队列能演示部分失败、重试和人工处理；
- 审核队列能演示通过、驳回、修改和重审；
- 素材详情可查看生产与审核追溯记录；
- 页面刷新后至少能恢复初始演示场景；
- 1440px 与 1920px 下可用，关键操作无明显遮挡；
- 控制台无错误，核心流程可以重复演示。
